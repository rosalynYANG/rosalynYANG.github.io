一线人员真正缺少的，通常不是另一个聊天框，而是一条能把资料、数据、判断、内容和合规边界连接起来的工作路径。

我围绕真实的一线任务，设计并实现了一套金融营销与服务助手：让使用者能够沿着“查资料—做判断—生成内容—风险预检—对客沟通”的路径完成工作，同时让重要结论保留来源，让数据保留时间口径，让人工审核留在最终出口。

## 我负责什么

- 从客户服务、营销协作与产品研究场景中抽象任务，定义系统边界与产品结构；
- 设计 Agent、Skills、知识检索和多轮会话工作流；
- 将能力封装为 MCP、OpenAI 兼容 API 与 HTTP Tool，适配不同智能体入口；
- 建立数据来源、时间口径、缺失值与人工复核规则；
- 完成鉴权、限流、会话隔离、自动化测试、容器部署与服务器运行方案。

## 为什么不做“万能问答框”

金融一线工作并不只是问一个问题。资料分散、指标口径不同、内部观点与外部表达边界不同，生成内容还要经过风险检查与人工确认。

因此，我把系统组织成任务型工作流：先识别任务和受众，再调用知识、数据、观点和素材工具；生成结果时保存来源、期间、截止日与缺失原因；最后执行机器预检，并把正式审核、授权与留痕交还给人。

## 七类已经实现的任务

1. **金融知识与客户服务**：支持多轮上下文、结构化结果，以及不同客户端的降级展示；
2. **营销素材 AI 搜索**：按产品、主题与热点连续追问，返回可继续处理的结构化素材；
3. **产品研究对比**：按同类规则选择样本，保存指标来源、单位、期间、截止日和缺失原因；
4. **金融内容与报告生成**：通过数据契约生成结构化报告，不让模型补写无来源的归因或展望；
5. **营销合规预检**：给出风险级别、命中片段、原因、修改建议和修订文本，但不替代正式审批；
6. **渠道拜访准备**：把市场主题、内部观点、产品数据、常见问题、素材与话术组织成一页式准备卡；
7. **市场事件转行动**：区分事实与观点，通过正式数据建立产品关联，再生成面向一线的沟通建议。

## 可信，比“看起来聪明”更重要

产品研究中的每项关键指标都携带来源、单位、期间与截止日。缺失值不会被写成零，也不会由模型自行估算；只有排名信息完整时才展示精确名次。内部准备稿和外部沟通稿采用不同边界，机器预检也始终明确保留人工复核。

这不是为了让结果显得保守，而是让 AI 真正进入高要求业务时仍然可解释、可追溯、可负责。

## 从原型到长期运行

同一套能力可以通过 MCP、OpenAI 兼容接口和 HTTP Tool 被不同 Agent 平台调用。工程底座覆盖 API 鉴权、按调用方限流、多轮会话隔离、链接安全、凭证加密存储、容器化、反向代理、健康检查与自动化测试。

因此，这个项目证明的不只是“我会使用 AI”，而是我能把金融理解、产品判断、工作流设计和工程交付连接成一套真正可以运行、维护与继续扩展的系统。
